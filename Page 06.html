Identity Layer

Workload Identity Federation — Mutual

Both ClaraVis and each supplier/3PL register a WIF identity before any A2A message exchange[cite: 8]. ClaraVis's ProcureGuard agent authenticates to external supplier agents using its GCP Service Account WIF token[cite: 8]. Each supplier agent presents its own WIF token, which ProcureGuard verifies against the pre-registered Agent Card before accepting any BidResponse or ACK[cite: 8]. No message from an unregistered WIF identity is processed[cite: 8]. WIF tokens are short-lived (1 hour) and automatically rotated[cite: 8]. Revocation is immediate via WIF pool membership removal[cite: 8].

Discovery Layer

A2A Agent Card Registry

Each supplier and 3PL agent publishes an Agent Card to a GCP-hosted A2A Agent Card registry at onboarding[cite: 8]. The Agent Card contains: WIF identity, A2A endpoint URL, supported message types, ISO 13485 certification status, and GDPR data processing agreement reference[cite: 8]. Agent Cards are signed by ClaraVis's Procurement Director (HITL-06) at onboarding and re-validated annually[cite: 8]. Revoked or expired Agent Cards immediately block that supplier from participating in A2A Commerce loops[cite: 8]. ProcureGuard queries the registry before every SourcingRequest broadcast — no cached identity lists[cite: 8].

Message Integrity

ECDSA P-256 Bi-directional Signing

Every A2A message — in both directions — is signed with ECDSA P-256[cite: 8]. The sender's public key is retrieved from the Agent Card registry at verification time[cite: 8]. This prevents message spoofing, MITM injection, and replay attacks[cite: 8]. Signature verification failure → message rejected + security alert to CISO + Cloud Monitoring event[cite: 8]. Signing keys rotated every 90 days via automated Cloud KMS workflow[cite: 8].

GDPR Framework

GDPR Art. 46 — Standard Contractual Clauses

Supplier agents outside the EEA: data transfer is covered by EU Standard Contractual Clauses (SCCs, 2021 Commission Decision) embedded in every supplier onboarding agreement[cite: 8]. SCC reference is included in each supplier's Agent Card metadata[cite: 8]. GDPR Article 30 Records of Processing: each Firestore audit document constitutes the processing record for the corresponding A2A transaction[cite: 8]. Data minimisation (Art. 5(1)(c)): A2A message schemas are defined to exclude personal data of supplier contacts — supplierId fields contain WIF machine identities only[cite: 8].

Lifecycle

Supplier Agent Lifecycle

Onboarding: supplier submits Agent Card + ISO 13485 certificate + DPA[cite: 8]. Legal Counsel (HITL-06) approves registration[cite: 7, 8]. Agent Card signed and added to registry[cite: 8]. WIF pool membership granted[cite: 8]. Test A2A handshake performed before production access[cite: 8]. Offboarding: WIF pool membership revoked immediately[cite: 8]. Agent Card marked REVOKED in registry[cite: 8]. In-flight A2A loops → circuit breaker state[cite: 8]. All prior Firestore audit records retained per ISO 13485 retention schedule (15 years)[cite: 8].

Incident Management

Compromised Agent Response

If a supplier agent's WIF identity is suspected compromised: immediate WIF pool revocation[cite: 8]. All pending A2A Commerce loops for that supplier → circuit breaker state[cite: 8]. CISO + Procurement Director alerted[cite: 8]. Firestore audit log reviewed for anomalous messages[cite: 8]. ECDSA signing key for ClaraVis rotated as precaution[cite: 8]. Any POs in PENDING state escalated to HITL-06 for manual review before issuance[cite: 8]. Full incident record written to Firestore with immutable timestamp[cite: 8].

Architecture Position

The swarm that knows its limits[cite: 8].

The circuit breaker layer is not defensive programming[cite: 8]. In a regulated medical device supply chain, a supplier risk score that silently fails is more dangerous than one that loudly escalates[cite: 8]. Every circuit breaker in this architecture has a defined human escalation target, a defined fallback state, and an immutable audit record that captures the degraded-mode operation[cite: 8]. The Orchestrator — previously unspecified — now carries the most critical circuit breaker definition in the swarm: the dead-letter queue, the ops runbook trigger, and the COO alert that ensures no message is silently dropped when the routing layer fails[cite: 8].

The MDR SLA hard escalation at hour 48 is not configurable[cite: 8]. It is encoded as a write-path constraint[cite: 8]. No agent state, no system outage, and no circuit breaker can suppress it[cite: 8]. The CSRD HITL-07 gate is not configurable either — no regulatory report is filed without human sign-off, regardless of deadline pressure[cite: 8]. This is what compliance as a structural property means in practice[cite: 8].
